## Architecture Decisions

- `globals.css` uses `@theme inline` (Tailwind v4).
- `DialogTrigger` / `TooltipTrigger` / `Button` use `render` prop (`@base-ui/react`, not Radix).
- Do not modify files in `components/ui/` — generated by shadcn CLI.
- Use `getAuthUserId(ctx)` from `"@convex-dev/auth/server"` for the authenticated `Id<"users">`. Never cast `identity.subject`.
- All curriculum tables now carry a `language: "en" | "fr"` field. English rows default to `"en"`; French rows to `"fr"`. Indexes `by_language_and_level` (on `units`) and `by_language_and_userId` (on `unitProgress`) support per-language filtering.
- `conjugaisonModules` and `orthographeModules` are French-only tables (`language: v.literal("fr")`), indexed `by_unit`.
- French vocabulary data lives in `data/french-vocab-{level}.json` (classified) and `data/french-vocab-{level}-by-unit.json` (unit-assigned). These are inputs to the seed script, not runtime assets.
- Routing: `/` is the bilingual picker (unprefixed, post-auth); learning routes live under `/[locale]/...` where `locale ∈ {"en","fr"}`; `/sign-in` stays unprefixed. The `NEXT_LOCALE` cookie is the source of truth for `<html lang>` in the root layout and is set by `next-intl`'s middleware when a user enters a locale route.
- i18n: `next-intl` with messages in `messages/{en,fr}.json`. Server pages call `getTranslations()`; client components call `useTranslations()`. Error labels in `lib/errors.ts` intentionally stay English-only — the `ErrorMessage`/`ErrorBanner` components do not depend on the i18n provider so they render on unauthenticated routes too.
- Module gating: English units have 6 modules in fixed order; French units have 8 modules (grammar → conjugaison → orthographe → reading → listening → writing → speaking → review). Conjugaison requires `grammarScore ≥ 70`; orthographe requires `conjugaisonScore ≥ 70`; reading unlocks from orthographe (FR) or grammar (EN). All other gates unchanged.
- AI evaluation: Convex actions branch on `unit.language`. French writing and speaking submissions use French DELF/DALF prompts; Whisper transcribes with `language: "fr"`. JSON output schema is identical across languages so `writingSubmissions` / `speakingSubmissions` shapes are uniform.
